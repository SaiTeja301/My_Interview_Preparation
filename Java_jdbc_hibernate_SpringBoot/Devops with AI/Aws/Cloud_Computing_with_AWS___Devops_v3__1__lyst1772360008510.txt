Cloud Service Models

3) SAAS : Software as a service

Cloud Service Models
====================
1) IAAS : Infrastructure as a service

2) PAAS : Platform as a service

3) SAAS : Software as a service

IAAS : Infrastructure as a service
----------------------------------
--> Provider will provide infrastructure 
    ex: Machines(servers), storage, network
--> We need to take care of platform and application

Your Responsibility: Operating systems, applications, data, runtime, middleware.

PAAS : Platform as a service
----------------------------
--> Provider will provider ready made platform to run our app ( Provider will take care of infrastructure and platform )
ex: AWS Elastic beanstalk

The provider handles the underlying infrastructure and the software environment (operating systems, middleware, databases, web servers). You just focus on your code.

Your Responsibility: Your application code, data, and configuration.


SAAS : Software as a service
-----------------------------
--> Application + Infrastructure + Platform all will be maintained by provider
--> Provider will give their application to run our business

ex: Zoom , Dropbox, Google Drive ........

EC2 (Elastic Compute Cloud)
===========================

-> Elastic Compute Cloud -> Most demanded service in AWS

-> Used to Create Virtual Machines/Servers/VM in AWS Cloud

==> EC2 Instance ==> Server / VM / Computer (laptop)

==> It's a paid service --> Hourly Billing

    11:15 AM --> 11:30 AM ==> 15 mins --> Billed for 1 hour
    09:15 AM --> 09:20 AM ==> 5 mins --> Billed for 1 hour
    09:15 AM --> 10:10 AM ==> 55 mins --> Billed for 1 hour

==> EC2 Instance minimum billing period is 1 hour

-> AWS provides t2.micro/t3.micro (6 months) of free ec2 instance to encourage learners and free tier account will get free credits as and when they practice any of the asked services by AWS

-> EC2 VM also have storage with EBS ( Ec2 Linux VM -> 8GB ( default ) , EC2 Windows VM -> 30 GB ( default ) EBS max -> 16 TB )

-> We use AMI(Amazon Machine Image) which represents Configuration required for machine 

  Windows AMI
  Ubuntu AMI
  RedHat AMI
  Amazon Linux AMI

-> To Secure access to EC2 VM we use Key-Pair (.pem) 
    
   -> One Key-Pair ( .pem ) can be used for multiple ec2-instances

-> We use Security Group to allow incoming and outgoing traffic ( In bound rules and Out Bound rules )
   
   -> One Security Group ( SG ) can be used for multiple instances

EC2 VM creation
===============

--> Create Key Pair( pem file ) 
   public key   ( aws will keep it )
   private key ( we get this )

--> Create  a Security Group and update inbound rules based on requirement
    
    HTTP :22
    HTTPS : 443
    SSH : 22
	..
	..

Note : We can create new key pair and Security Group at the time of instance creation also.

--> Create EC2 Instance / Server / VM

    -> Give a name VM
    -> SELECT AMI
    -> Instance Type
    -> Select Key-pair ( choose existing one or create a new )
    -> Select Security Group ( choose existing one or create a new )
    -> Select EBS storage ( keep it default )
    -> Launch Instance 

Types of IP's in AWS 
======================

1) private ip 
2) public ip 
3) elastic ip

-> private IP -> Fixed Ip -> It is used for internal Communication (within VPC).

-> public IP -> Dynamic IP -> It is used to connect with EC2 VM from outside. When we restart our VM the public IP gets changed.

Dynamic Public IP --> 3.109.213.248    13.235.79.233

Fixed private IP --> 172.31.7.164   172.31.7.164

-> If we want fixed public IP -> Elastic IP -> ( Elastic IP s are paid ) --> Charges would be applied and bills would be generated
